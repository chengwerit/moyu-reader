## 项目定位

本地优先的网页电子书阅读器。零注册、零安装、零上传，数据存在项目目录的
`data/` 下，整个文件夹可复制迁移。

开源地址：https://github.com/chengwerit/moyu-reader （MIT）

完整说明见 [项目说明.md](../项目说明.md)。

## 不可违反的硬约束

### 1. 文件编码（违反会导致程序无法启动）

| 文件 | 必须 | 原因 |
|---|---|---|
| `*.ps1` | UTF-8 **with BOM** + CRLF | PS 5.1 读无 BOM 的 UTF-8 会把中文当乱码并截断语法结构，报错还指向无关的行 |
| `*.bat` | **纯 ASCII** + CRLF | cmd 按 GBK 读批处理，UTF-8 中文破坏命令行解析 |

**这两条正好相反**，极易搞混。`.gitattributes` 已固化，改文件时别破坏它。

改完 `.ps1` 记得用脚本确认 BOM 还在（编辑器另存可能丢掉）。

### 2. 隐私边界

- `data/` 里是用户书籍、笔记、书签、设置 —— **绝不入库**，`.gitignore` 已排除
- 不做账户体系，不上传任何数据到服务器
- AI 伴读是自带 Key 模式，请求从浏览器直连用户自己填的服务地址，零中转

这是产品的核心立意，改动时不要破坏它。

### 3. 三处容易引入 bug 的实现

- **Service Worker 绝不能缓存 `/api/`** —— 否则书籍数据进 Cache Storage，
  读到过期内容且极难排查。当前实现对 `/api/` 直接放行。
- **服务端不能把整库缓存在内存** —— 用户手动删改 `data/` 后，
  下次写入会把内存旧值写回磁盘，表现为「删了又复活」。
  `server.ps1` 每次请求都从磁盘读。
- **`js/db.js` 有两套后端**（`FILE` 与 `IDB`），新增方法必须两边都实现，
  否则 `file://` 打开时崩。

## 架构决策（改之前先理解为什么）

**为什么数据默认存文件夹而不是 IndexedDB？**
用户最初的诉求是「换电脑能接着用」。IndexedDB 跟着浏览器走，
文件夹跟着人走 —— 后者才符合直觉。IndexedDB 保留为 `file://` 直开时的兜底。

**为什么不打包成单 HTML 文件？**
`file://` 下 ES 模块受同源策略限制，彻底解决需要打包器把模块合并。
代价是构建步骤会破坏「解压即用、源码可读」的特点。当前用双后端方案绕过。

**为什么服务端用 PowerShell 而不内置 Node？**
面向非技术用户分发，不能假设对方装了任何运行环境。PowerShell 是 Windows 自带的，
且 `HttpListener` 免管理员可用（已实测）。

**为什么第三方库要打进 `lib/`？**
若从 CDN 加载，首次访问要联网，且断网体验差 —— 与「双击即用、断网可用」的
卖点冲突。代价是仓库变大（约 1.5MB 依赖），值得。

## 环境注意事项

- profile 里常驻 `http_proxy`。Node/脚本访问 `127.0.0.1` 会失败，
  用 `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY <cmd>`
- **后台进程**（服务器、调试浏览器）必须用后台任务方式保持，
  普通 shell 的 `&` 会随命令结束被回收
- **Node 里 spawn 子进程会 EBUSY**（`spawnSync git/curl EBUSY`），
  涉及外部命令的任务改用 Bash
- 含中文的路径不要硬编码进脚本，用 `$PSScriptRoot` 动态定位

## GitHub 推送

`git push` 在本机不可用（git 协议必经 github.com，经代理间歇 502）。
改用 REST API 的 Git Data API 推，能得到单个干净提交。

Token 用 `git credential fill` 取，经环境变量传入，全程不落盘。

**推完必须校验字节**：用 API 取回 base64 解码，确认 BOM、行尾、中文完好。
不校验的话编码可能在传输中损坏，用户下载后双击没反应且难查。

## 验证工作流

改完代码必须验证，两套脚本：

```bash
node verify.cjs           # 12 项功能检查
node verify-portable.cjs  # 18 项便携性与落盘检查
```

支持环境变量：`CDP_PORT`、`APP_PORT`、`DATA_DIR`。

测试脚本用固定 `sleep` 会因冷启动（CDN 依赖加载慢）假失败，
已改为 `waitFor()` 轮询 —— 新增等待请沿用这个方式。

## 待办与已知限制

- Mac / Linux 启动器未做（当前只有 Windows 的 `.bat`）
- 极老的 `.doc` 二进制格式可能解析失败，建议另存 `.docx`
- 扫描版 PDF 无文本层，只能看图，不能搜索划线
- MOBI / AZW3 的 KF8 压缩流只做尽力解析，复杂文件可能失败
- `library.json` 存全量元数据，上万本书时写入会变慢，届时该上数据库
